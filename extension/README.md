# ToxiCheck Extension — MVP

Самостоятельное расширение Manifest V3 для Chrome и Edge. Использует существующий POST /api/analysis (source: label); не требует изменений БД, OCR или PWA.

## Установка и запуск

1. По умолчанию используется удалённый сервер ToxiCheck; локальный backend запускать не требуется.
2. Откройте chrome://extensions или edge://extensions, включите режим разработчика.
3. Нажмите «Загрузить распакованное расширение», выберите папку extension.
4. По умолчанию используется https://toxicheck.195.209.209.111.sslip.io/api. Для локальной разработки откройте настройки через шестерёнку и выберите http://localhost:8000/api и сохранить настройки с разрешением доступа. При обновлении с 0.1.0 старый стандартный localhost заменяется на удалённый сервер, автоматический режим отключается; другие адреса сохраняются.
5. Выделите состав на странице и выберите контекстное меню «Проверить состав в ToxiCheck» либо кнопку в popup. Кнопка «Найти состав на странице» запускает эвристический поиск.
6. По желанию включите автоматический режим переключателем в popup (отдельное сохранение не требуется) для Ozon, Wildberries и Яндекс Лавки. После установки расширения обновите уже открытые вкладки.

Автоматический режим выключен до явного согласия. Запросы выполняются в service worker с обязательным разрешением на сервер ToxiCheck и дополнительным разрешением на выбранный пользовательский API, без cookies; при анализе также передаются UUID персональных исключений; полный HTML, URL и другие данные страницы не передаются. Отправляется найденный или выбранный текст состава и список идентификаторов исключений. Результат отображается в панели Shadow DOM. Отсутствие ингредиента в результате не означает его отсутствие в товаре.

## Перемещение панели

Перетащите окно за заголовок ToxiCheck. Оно остаётся в пределах видимой области; позиция сохраняется при повторном открытии в той же вкладке до перезагрузки страницы. Для перемещения клавиатурой установите фокус на заголовок и используйте стрелки.

## Персональные исключения

В popup откройте «Мои предпочтения», найдите ингредиент по названию или E-коду и добавьте его в список. Также можно добавлять и удалять исключения из карточки ингредиента. Список хранится в chrome.storage.local, передаётся в preferences.excludedIngredientIds при каждом анализе. Персональный вердикт рассчитывается существующим API, исключения выделяются отдельно от нормативной оценки. При возврате из изменённой карточки анализ выполняется повторно. Синхронизация с гостевым профилем PWA пока не реализована.

## Карточки ингредиентов

Результат разделён на пищевые добавки с E-кодами, остальные ингредиенты и нераспознанные позиции. Цветовые статусы соответствуют PWA. «Нет предупреждений» не означает гарантированную безопасность; без правил нейтральный результат отображается как «Нет данных». По нажатию на ингредиент загружается GET /api/ingredients/{id}: описание, функции, происхождение, синонимы, условия применения и источники. Возврат к результату не выполняет повторный анализ.

## Проверка

```sh
node --test extension/tests/*.test.cjs

node --check extension/content.js
node --check extension/popup.js
```

## Архитектура и ограничения

- extract.js: эвристики по видимым заголовкам, соседним элементам и текстовым блокам.
- presentation.js и panel.css: оформление, статусы и группировка результатов.
- content.js: обнаружение изменений DOM, панель результата и ручной запуск.
- background.js: проверка разрешений, запросы к существующему API и контекстное меню.
- popup: включение автоматического режима и ручной запуск.
- options: отдельная страница настройки API для разработчиков.

Это экспериментальный MVP на JavaScript без сборщика и внешних зависимостей. TypeScript/Vue можно добавить при расширении UI. Поддержка конкретной разметки магазинов пока не подтверждена на реальных карточках; закрытые/свёрнутые блоки, iframe и составы на изображениях могут быть недоступны. Нет ML-классификатора текста, синхронизации исключений, OCR выбранной области, мобильной версии и публикации в магазинах расширений.

Следующий этап: собрать анонимизированные DOM-фрагменты и эталонные составы трёх площадок, оценить precision/recall извлечения, добавить адаптеры и сравнить эвристики с классификатором.
